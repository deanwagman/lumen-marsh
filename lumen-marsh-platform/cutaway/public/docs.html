What Cutaway is

Cutaway is the local booth for Lumen Marsh. The guest room and Control Tower are open at the same time, and the producer cues sit outside both rooms. It is not a park domain, not a seventh application, and not a public host.

One static page in the local Compose env. compose.yaml does not start it.

  • Left: the guest app, Today. Best Next lives there.
  • Right: Control Tower, the existing local supervisor session.
  • Rail, outside both frames: four producer triggers.
  • Strip under the frames: the last VenueOps recommendation, and whether the guest projection changed.

The rail fires producers only. Place hold, accept, dismiss, and publish stay inside Control Tower. The strip reads VenueOps, not the producer logs: pending weather, pending reliability, and unpublished flow on the operator side; guest advisory and Best Next on the guest side.

Lightning, vibration, and mangrove disruption keep the guest frame on Today and bring the matching Control Tower card into view. Clear the storm leaves both frames where they are. The tower column is wide enough for the workstation layout, so the attention queue stays on screen.

If VenueOps cannot be read, Cutaway covers both rooms with one offline state and disables the rail until the stack is healthy. The guest app and Control Tower do not each show their own error.

How to open it

  1. From lumen-marsh-platform, copy .env.example to .env and set NWS_USER_AGENT.
  2. Run ./scripts/dev-up.sh for the local supervisor session. ./scripts/dev-up.sh --oidc does not start Cutaway.
  3. Open http://localhost:3090. This page is Docs.

There is no Cognito step on this page. The console frame is the local supervisor session. If you open http://127.0.0.1:3090 instead, the local console image must have been built with that origin allowed. The production console image does not allow framing. docker compose -f compose.yaml does not pass that exception.

What each rail button does

Simulation has to be on. The local Compose override already enables it. Each button posts an empty JSON body, the same call the lifecycle scripts use, and shows Fired or Failed.

Rail buttons and the producer call each one makes
Rail button Call Before anyone clicks in the tower
Lightning hold POST http://localhost:8000/api/v1/simulation/scenarios/hold-conditions Pending weather on the strip. Control Tower scrolls that weather card into view. The guest frame stays on Today, and the advisory stays quiet.
Clear the storm POST http://localhost:8000/api/v1/simulation/scenarios/clearance-period The monitor moves to the clearance scenario. The frames stay where they are. Recovery commands still happen in Control Tower.
Cypress Coil vibration POST http://localhost:8200/simulation/scenarios/cypress-coil-vibration Pending reliability on the strip. Control Tower scrolls that attention card into view. The guest frame stays on Today and stays quiet.
Mangrove disruption POST http://localhost:8100/simulation/scenarios/mangrove-disruption Unpublished flow on the strip. Control Tower scrolls that attention card into view. The guest frame stays on Today. Best Next does not treat Mangrove as down.

Mangrove disruption reuses one recommendation id. After that id is dismissed, published, or otherwise no longer a new pending review, another click will not open a new unpublished card. The strip then shows a reset note. It is not a button. From lumen-marsh-platform, run ./scripts/reset-demo.sh --confirm and start the stack again.

What the operator still clicks

Cutaway does not hold a ride, accept a recommendation, dismiss one, or publish guest copy. Those clicks stay in Control Tower.

  • Lightning. Review the weather recommendation, open the incident, and place the hold. Publish guest advisory is the click that lets Today show it. Until that publish, the strip’s guest advisory stays Quiet and the projection stays Unchanged.
  • Vibration. Accept the reliability recommendation and work the order through inspection and testing. Reliability Intelligence never creates the work order. Guests still must not see work-order numbers, asset codes, or internal notes.
  • Mangrove. Approve if you want, then publish as a supervisor. Best Next stays empty until that publish.
  • Clear the storm. Clearance is a producer scenario. Return to service is still an operator command in the tower.

What the guest must not see until publish

Until a supervisor publishes:

  • No park advisory on Today after lightning. Pending weather is an operator card.
  • No reliability internals after vibration. The guest projection stays unchanged.
  • Best Next does not rank Mangrove Run down, and does not show the unpublished guest message, after mangrove disruption.

The strip is that split. Operator rows come from the operator dashboard. Guest rows come from guest advisories and published flow recommendations. A pending card with a quiet guest row means the publish has not happened.
